# AI Go Architecture Designer：产品路线与开发总计划

## 1. 产品定位

这是一个面向 Go 开发者的 AI 项目设计与脚手架平台。

核心链路：

```text
自然语言需求
    ↓
需求理解
    ↓
数据库设计
    ↓
可编辑 ER 图
    ↓
Go Model
    ↓
系统架构设计
    ↓
可编辑架构图
    ↓
Go 项目生成
    ↓
Build / Test / Vet
    ↓
Agent 修复
```

核心原则：

- AI 负责理解、推理、规划和提出修改。
- DSL 负责保存项目设计的真实状态。
- Canvas 负责可视化和人工编辑。
- Generator 负责确定性代码生成。
- Validator 负责验证生成结果。
- 用户拥有最终确认权。

## 2. 阶段总览

| 阶段 | 名称 | 核心产物 |
|---|---|---|
| 0 | 基础设计与技术基座 | DSL、项目骨架、接口 |
| 1 | 自然语言 → ER DSL | 数据库设计 Agent |
| 2 | ER DSL → ER Canvas | 可编辑 ER 图 |
| 3 | ER DSL → Go Struct | Go Model Generator |
| 4 | 多轮对话与 Context | Context / Session |
| 5 | 架构设计 | Architecture DSL + Canvas |
| 6 | 项目生成 | Go Project Generator |
| 7 | 自动验证闭环 | Build/Test/Repair Loop |
| 8 | 产品化 | 完整 Web 产品 |

## 3. Stage 0：基础设计

任务：

- 定义 Project DSL
- 定义 ER DSL
- 定义 Architecture DSL 初版
- 定义 ID、version、命名规则
- 定义 DSL validation
- 搭建 Go Backend
- 搭建 React + TypeScript Frontend
- 接入 Eino
- 建立测试基础设施

验收：DSL 可以序列化、反序列化、校验，前后端可以传递，Agent 可以调用 Tool。

## 4. Stage 1：自然语言 → ER DSL

任务：

- Requirement extraction
- Entity extraction
- Field extraction
- Relation inference
- PK / FK / unique / index 推断
- Structured Output
- Schema validation
- 歧义与假设处理

验收：给出业务需求后能够得到合法、可编辑的 ER DSL。

## 5. Stage 2：ER Canvas

推荐 React + TypeScript + React Flow。

任务：

- TableNode
- Field 展示
- PK/FK
- Relation Edge
- 拖动、缩放、平移
- 新增/删除表
- 新增/删除/修改字段
- 新增/删除关系
- JSON 导入导出
- 自动布局

原则：

> Canvas 是 DSL 的编辑器，不是 Source of Truth。

## 6. Stage 3：Go Struct

任务：

- DB type → Go type
- 命名转换
- GORM tag
- association
- import 管理
- gofmt
- 编译测试

原则：

> LLM 决定数据模型，确定性 Generator 负责生成代码。

## 7. Stage 4：Context 管理

Context 分层：

```text
System
Project
Decision
Working
Recent Conversation
```

任务：

- Session
- Token budget
- Context compaction
- Decision memory
- Relevant context retrieval
- Version snapshot
- Conflict detection

核心原则：

> Project DSL 是事实，Context 是模型当前看到的视图。

## 8. Stage 5：Architecture

任务：

- Architecture DSL
- Node / Edge
- Architecture Agent
- 从 ER 推导模块
- Architecture Canvas
- 用户编辑
- Architecture validation

初版节点：

- Router
- Handler
- Service
- Repository
- Database
- Redis
- MinIO
- External API

## 9. Stage 6：项目生成

生成：

```text
cmd/server/
internal/
  handler/
  service/
  repository/
  model/
  middleware/
  config/
  router/
pkg/
migrations/
configs/
go.mod
README.md
```

任务：

- Project Generator
- Model Generator
- Handler Generator
- Service Generator
- Repository Generator
- Router Generator
- Config Generator

第一版只生成稳定骨架，不生成复杂业务逻辑。

## 10. Stage 7：验证闭环

```text
Generate
 ↓
go mod tidy
 ↓
go test ./...
 ↓
go vet ./...
 ↓
go build ./...
 ↓
Error?
 ↓
Agent 分析
 ↓
修改
 ↓
重新验证
```

必须有：

- Command Runner
- 超时
- 输出限制
- Retry limit
- Error parser
- Repair Agent
- Human approval

## 11. Stage 8：产品化

最终包含：

- 用户/项目管理
- 多版本
- ER Canvas
- Architecture Canvas
- AI Chat
- Code Viewer
- Validation Log
- JSON/SQL/PNG/SVG/ZIP 导出
- Agent Run / Tool Call / Token / Error 可观测性

## 12. 推荐路线

第一阶段真正可展示的 MVP：

```text
自然语言
 ↓
ER DSL
 ↓
ER Canvas
 ↓
用户编辑
 ↓
Go Struct
```

完成这个之后再做 Architecture 和 Project Generator。

## 13. 最终评价指标

- DSL validation rate
- Requirement coverage
- Human correction rate
- Go compile success rate
- First-build success rate
- Auto-repair success rate
- Token consumption
- Context compression loss
- 平均生成时间
