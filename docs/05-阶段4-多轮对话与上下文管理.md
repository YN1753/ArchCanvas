# Stage 4：多轮对话与 Context 管理

## 目标

用户可以连续几十轮修改项目。

## 1. Context 分层

```text
System Context
Project Context
Decision Context
Working Context
Recent Conversation
```

## 2. Source of Truth

真实状态：

```text
Project DSL
Decision Store
Version Store
```

Context 只是：

> 当前模型需要看到的信息。

不要让摘要成为项目事实。

## 3. Context Manager

达到 Token 阈值后：

```text
检查
 ↓
保留永久事实
 ↓
保留用户决策
 ↓
删除已完成临时任务
 ↓
压缩旧对话
 ↓
保存新 Context
```

不要简单做：

```text
10000 tokens → 一段 summary
```

应该结构化：

```json
{
  "facts": [],
  "decisions": [],
  "constraints": [],
  "pendingTasks": [],
  "conflicts": [],
  "summary": ""
}
```

## 4. Retrieval

用户说：

> “把订单表改一下。”

只召回：

- orders
- 最近相关对话
- 相关 decisions
- 当前 ER DSL

而不是全部历史。

## 5. Version

重要确认点保存：

```text
v1
v2
v3
```

支持恢复。

## 6. Eino

可以结合 Eino 的 Session、Middleware、Runner、Interrupt/Resume 等能力实现多轮生命周期和上下文处理。官方 ADK 文档目前也把 context management、middleware 和 session 列为核心能力。citeturn0search8turn0search2

## 7. 验收

连续 30~50 轮修改：

```text
创建 users
→ products
→ orders
→ 删除 category
→ 增加 favorites
→ 修改 email
```

最终 DSL 必须等于用户确认后的结果。
