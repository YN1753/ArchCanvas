# Stage 3：ER DSL → Go Struct

## 目标

把确认后的 ER DSL 稳定生成 Go Model。

核心原则：

> LLM 不负责最终代码生成。

## 1. 生成链路

```text
ER DSL
 ↓
Validation
 ↓
Type Mapping
 ↓
Generator
 ↓
gofmt
 ↓
Go Struct
```

## 2. 类型映射

第一版固定：

| DB | Go |
|---|---|
| BIGINT | uint64/int64 |
| INT | int |
| VARCHAR | string |
| TEXT | string |
| BOOLEAN | bool |
| DATETIME | time.Time |
| DATE | time.Time |
| DECIMAL | decimal.Decimal |

实际采用哪一种由项目配置决定。

## 3. 命名

```text
users → User
user_profiles → UserProfile
created_at → CreatedAt
```

建立统一 naming package。

## 4. GORM

例如：

```go
type User struct {
    ID        uint64    `gorm:"primaryKey"`
    Email     string    `gorm:"size:255;uniqueIndex;not null"`
    CreatedAt time.Time
}
```

关系生成策略也必须固定。

## 5. 测试

建立 fixture：

```text
fixtures/user_order.json
expected/user_order.go
```

使用：

- `go/parser`
- `go/format`
- `go/types`

检查语法与类型。

## 6. 不要做

Stage 3 暂时不要生成：

- Service
- Handler
- Repository
- CRUD
- 复杂业务代码

## 7. 验收

完整链路：

```text
自然语言
 ↓
ER DSL
 ↓
用户编辑
 ↓
Go Struct
 ↓
gofmt
 ↓
编译通过
```

这就是第一个正式 MVP。
