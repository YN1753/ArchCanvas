# Stage 5：架构设计与 Architecture Canvas

## 目标

在 ER 稳定后，设计 Go 项目架构。

```text
需求 + ER DSL + 技术栈
        ↓
Architecture Agent
        ↓
Architecture DSL
        ↓
Architecture Canvas
```

## 1. Architecture DSL

```json
{
  "nodes": [],
  "edges": []
}
```

Node：

```json
{
  "id": "user_service",
  "type": "service",
  "name": "UserService",
  "properties": {}
}
```

Edge：

```json
{
  "id": "handler-service",
  "source": "handler",
  "target": "service",
  "type": "call"
}
```

## 2. 初版节点

- Router
- Handler
- Service
- Repository
- Database
- Redis
- MinIO
- External API

## 3. 典型架构

```text
Router
 ↓
Handler
 ↓
Service
 ↓
Repository
 ↓
MySQL
```

基础设施：

```text
Service → Redis
Service → MinIO
Service → External API
```

## 4. Agent 职责

根据：

- 需求
- ER
- 技术栈
- 用户约束

提出：

- 模块
- 依赖
- 数据流
- 基础设施

但不直接输出 React Flow JSON。

## 5. Canvas

继续复用同一 Canvas Engine：

```text
Canvas Engine
 ├── ER Node
 └── Architecture Node
```

数据模型分开。

## 6. Validation

检查：

- source/target 存在
- 非法依赖
- Handler 直接访问 DB
- Repository 依赖 Handler
- 循环依赖
- 孤立节点

## 7. 用户修改

如果用户删除 Redis，必须记录 Decision：

```text
Redis rejected by user
```

下一次 Agent 不得无理由恢复。

## 8. 验收

```text
需求
 ↓
ER
 ↓
Architecture
 ↓
用户编辑
 ↓
导出 Architecture DSL
```
