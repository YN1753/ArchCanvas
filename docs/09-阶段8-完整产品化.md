# Stage 8：完整产品化

## 目标

把技术 Demo 变成真正可以使用和展示的 Web 产品。

## 1. 工作区

```text
┌──────────────────────────────────────────────┐
│ Project / Version / Export                   │
├──────────────┬───────────────────────────────┤
│ AI Chat      │ Canvas                        │
│              │ ER / Architecture             │
│ Requirements │                               │
│ Decisions    │                               │
├──────────────┴───────────────────────────────┤
│ Code / SQL / Validation / Logs               │
└──────────────────────────────────────────────┘
```

## 2. Project Lifecycle

```text
Draft
 ↓
ER Designing
 ↓
ER Confirmed
 ↓
Architecture Designing
 ↓
Architecture Confirmed
 ↓
Generating
 ↓
Validating
 ↓
Ready
```

## 3. Version

支持：

- 查看
- 对比
- 恢复
- 导出

## 4. 导入导出

- JSON
- SQL

- PNG

Architecture：

- JSON
- SVG
- PNG

Project：

- ZIP

Git integration 可以后置。

## 5. Agent 体系

最终可以有：

```text
Main Agent
 ├── Requirement
 ├── Database
 ├── Architecture
 ├── Generator
 └── Validator
```

但不要为了 Multi-Agent 而 Multi-Agent。

Eino 官方示例已经覆盖 Supervisor、Plan-Execute-Replan、Multi-Agent、GraphTool 等模式，应该在真正出现复杂协作需求后再引入。citeturn0search1turn0search3

## 6. 可观测性

记录：

```text
Agent Run
Tool Call
Token
Latency
Error
Retry
Context Compression
```

目标是能够回答：

> 为什么这次 Agent 做错了？

## 7. 安全

严格限制：

- Shell
- File System
- Network
- Database
- Git
- Migration

按 Tool 做权限隔离。

## 8. 最终验收

用户从零开始：

```text
输入需求
 ↓
AI 生成 ER
 ↓
用户编辑 ER
 ↓
生成 Go Struct
 ↓
AI 设计架构
 ↓
用户编辑架构
 ↓
生成 Go 项目
 ↓
自动 Build/Test
 ↓
修复问题
 ↓
导出项目
```

整个过程不依赖人工复制粘贴。
