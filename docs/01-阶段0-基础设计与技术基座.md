# Stage 0：基础设计与技术基座

## 目标

先确定整个系统的数据边界，而不是马上堆 Agent。

最终需要形成：

```text
Project DSL
 ├── Database / ER DSL
 ├── Architecture DSL
 ├── Decisions
 └── Metadata
```

## 1. ER DSL

建议初版：

```json
{
  "version": "1.0",
  "tables": [],
  "relations": [],
  "indexes": []
}
```

Table：

```json
{
  "id": "table_user",
  "name": "users",
  "fields": [],
  "position": {"x": 100, "y": 100}
}
```

Field：

```json
{
  "id": "field_user_id",
  "name": "id",
  "type": "BIGINT",
  "nullable": false,
  "primaryKey": true,
  "unique": false
}
```

Relation：

```json
{
  "id": "relation_user_order",
  "sourceTable": "table_user",
  "sourceField": "field_user_id",
  "targetTable": "table_order",
  "targetField": "field_order_user_id",
  "cardinality": "one_to_many"
}
```

## 2. Validation

必须检查：

- ID 唯一
- table name 唯一
- field name 唯一
- PK/FK 引用存在
- relation 两端存在
- type 合法
- cardinality 合法

## 3. 前端

推荐：

- React
- TypeScript
- `@xyflow/react`

React Flow 的核心就是 nodes、edges 和 viewport，并支持自定义节点与交互，非常适合这个产品的 Canvas。citeturn0search4turn0search10

必须设计：

```text
DSL ↔ Canvas Adapter ↔ React Flow
```

React Flow JSON 不作为领域模型。
