## 2. 评测集设计说明

评测用例集持久化于 `server/testdata/eval/cases.json`，分为两个核心测试组：
1. **歧义决策评测集（25 条需求）**：
   - 覆盖应澄清场景（15 条）：短模糊需求（如“做个商城”、“登录”）、元疑问、缺少主体单据短语等；
   - 覆盖放行场景（10 条）：电商交易、博客社区、高校教务、报销审批、会议室预约等具备完整业务链路与多主体的需求；
   - 验证代码层决策门禁叠加效果：0 误伤正常输入，彻底拦截极短与模糊脑补输入。
2. **建模质量与端到端编译评测集（10 个典型业务场景）**：
   - 涵盖电商、内容社区、教务选课、企业 RBAC 权限、IoT 物联网、仓储 WMS、会议室预约、看板任务、医院挂号、报销审批；
   - 质检规则：
     - [x] **主键完整性**：每张实体表必须声明且仅声明有效的物理主键（`IsPrimaryKey == true`）；
     - [x] **端点引用有效性**：关系两端的源实体与目标实体必须合法存在于模型池中；
     - [x] **多对多关联规范性**：多对多技术中间表和关联声明一致；
     - [x] **端到端工程编译验证**：通过 `GeneratorService` 输出工程后，在隔离临时目录执行真实 `go mod tidy` + `go build -o server_bin ./cmd/server` 零错误零警告退出；
     - [x] **Go 静态分析合规**：生成的全套 Model / Handler / Service / Repository 严格通过 `go vet ./...` 检查。
